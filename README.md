# s3backup

Утилита для Keenetic с Entware. По расписанию скачивает готовые резервные
копии из S3-совместимого хранилища на отдельный USB-диск и проверяет их размер
и SHA-256. Настройки и управление доступны через консольное меню `s3backup`.

## Установка на роутер

Нужны Entware, подключённый USB-диск и доступ к SSH Entware от root. Для
установки из GitHub нужен `curl`. Если его ещё нет, выполните
`opkg update && opkg install curl ca-bundle`.

В SSH-сеансе скачайте и запустите мастер:

```sh
s3backup_setup=$(mktemp -d) &&
  curl -fsSL https://raw.githubusercontent.com/YBakalenko/s3backup/refs/heads/main/install.sh \
    -o "$s3backup_setup/install.sh" &&
  sh "$s3backup_setup/install.sh" --download
```

Установщик получит остальные файлы из того же репозитория, установит нужные
пакеты Entware и откроет мастер. Для установки из локального каталога
скопируйте на роутер `install.sh`, `s3backup` и `S98s3backup`, затем запустите
`sh install.sh` в этом каталоге. Подход к установке вдохновлён
[XKeen от JamesZero](https://github.com/jameszeroX/XKeen/wiki/Install-script).

В мастере укажите HTTPS-адрес S3, регион, бакет, префикс и тип адресации.
Для роутера используйте отдельный ключ с правами перечисления и чтения
объектов. Мастер скрывает ввод ключей и сохраняет их в файле
`/opt/etc/s3backup/rclone.conf` с правами `0600`.

Выберите новый или пустой каталог на HDD. Мастер проверяет UUID диска,
убеждается, что он отличается от носителя Entware, и проверяет права `0700`
на каталог и `0600` на файлы. Если архивы содержат секреты, ограничьте
сетевой доступ к этому каталогу.

По умолчанию мастер предлагает ежедневный запуск в 05:00 UTC и хранение
30 дней. Для московского времени укажите пояс `MSK-3`. После сохранения
настроек проверьте доступ и выполните первый проход:

```sh
s3backup check
s3backup run
s3backup start
```

## Управление

| Команда | Действие |
| --- | --- |
| `s3backup` | Открыть меню |
| `s3backup configure` | Изменить S3, каталог, время или срок хранения |
| `s3backup check` | Проверить доступ к префиксу и наличие манифестов |
| `s3backup run` | Выполнить проход сейчас |
| `s3backup start` | Включить расписание и автозапуск |
| `s3backup stop` | Выключить расписание и остановить текущий проход |
| `s3backup restart` | Остановить и снова включить расписание |
| `s3backup status` | Посмотреть время запуска и результат последней попытки |
| `s3backup logs` | Посмотреть журнал |
| `s3backup uninstall` | Удалить программу и её задание, сохранив конфигурацию и архивы |

Планировщик Entware проверяет время раз в минуту. Обращение к S3 происходит
при наступлении заданного срока. Ручной проход засчитывается в текущий день.
После запуска роутера пропущенный срок подхватывается, когда Entware и HDD
снова доступны. При отключённом или подменённом диске проход завершается
ошибкой.

## Удаление с роутера

В SSH-сеансе Entware выполните `s3backup uninstall` или выберите «Удалить
утилиту» в меню `s3backup`. Подтвердите удаление ответом `да`.

Утилита остановит текущее копирование, выключит расписание и удалит
команду, задание `cron` и стартовый скрипт. Архивы на HDD, настройки и ключи
S3 в `/opt/etc/s3backup`, а также журналы в `/opt/var/lib/s3backup`
сохранятся. Установленные пакеты Entware останутся доступны другим службам.

## Какие объекты скачиваются

`s3backup` поддерживает пары в формате резервных копий TekStudio. Для
`backups/snapshot-001.tar.zst` манифест называется
`backups/snapshot-001.tar.zst.manifest.json`. Пример манифеста:

```json
{
  "snapshotId": "snapshot-001",
  "bucket": "my-bucket",
  "objectKey": "backups/snapshot-001.tar.zst",
  "snapshotAt": "2026-11-12T02:30:00.000Z",
  "sizeBytes": 123456,
  "sha256Ciphertext": "64 шестнадцатеричных знака SHA-256"
}
```

На диске пары лежат в `snapshots/<snapshotId>/`. Архив без манифеста
пропускается. Если манифестов нет, проход пропускает загрузку и очистку.
При ошибке существующей пары очистка откладывается. Срок хранения считается
от даты снимка, а последняя проверенная копия сохраняется.

## Переход с tkbackup

На роутере остановите старое задание командой `tkbackup stop`. Установите
`s3backup` и укажите в мастере прежний источник S3 и каталог на HDD. Формат
локальных копий совместим с `tkbackup`, поэтому исправные архивы сохранятся.
Введите ключи S3 и прежние параметры расписания в мастере новой утилиты,
проверьте первый проход и включите расписание командой `s3backup start`.

## Проверки

Для проверок в Linux нужны Bash, Python 3, jq, flock и обычные системные
утилиты. Запустите `python3 tests/test_s3backup.py` из корня репозитория.
Тесты используют временные каталоги и имитацию S3. Для сборки jq без
Oniguruma задайте `S3BACKUP_REQUIRE_NO_ONIG=1`.
